# Kuka Anomaly Detection

This repository contains a refactored version of the exploratory Kuka anomaly detection notebooks. The main project goal is to compare Autoencoder (AE) and Adversarial Autoencoder (AAE) approaches for Kuka anomaly detection. The notebooks remain available for analysis history, while reusable code now lives under `src/`.

## Project Structure

```text
config/
  config.yaml              # Dataset paths, model hyperparameters, output paths
src/
  config.py                # Repo-root path resolution and config loading
  data/                    # Kuka loading, validation, scaling, splitting, windows
  experiments/             # Repeatable experiment configs, runner, summaries, plots
  models/                  # ConvAE1D and Discriminator1D
  training/                # Training loops, full training entry point, smoke test
  evaluation/              # MSE scoring and threshold-based metrics
tests/                     # Focused pathing, data, and model-shape tests
KukaVelocityDataset/       # Expected location for .npy dataset files
```

## Environment Setup

Use Python 3.11 for the most reproducible team setup. Python 3.10-3.12 should also work with the current code, but newer scikit-learn and PyTorch wheels are easiest to align on Python 3.11.

```powershell
conda create -n kuka-ml python=3.11
conda activate kuka-ml
```

Install the base, hardware-independent dependencies:

```powershell
python -m pip install -r requirements.txt
```

Install PyTorch separately so each machine can choose the correct hardware build. For a standard CPU/default install, follow the command generated by the official PyTorch selector for your OS.

For NVIDIA systems that should use CUDA 12.8 wheels:

```powershell
python -m pip install -r requirements-cu128.txt
```

Omar's local read environment can be used for local checks on his device:

```powershell
& "C:\Users\omarh\anaconda3\envs\myTensorFlowEnv\python.exe" -m src.training.smoke_test
```

## Experiments

Notebook experiments are now represented in `config/experiments.yaml`. This keeps repeated runs simple and avoids copying notebook cells.

The ML review of the notebook and the recommended next experiments are documented in `docs/experiment_recommendations.md`. The runnable recommended set is also available through `config/recommended_experiments_queue.yaml`.

List available experiments:

```powershell
python -m src.experiments.run --list
python -m src.experiments.run --list --include-disabled
```

Preview what would run without training:

```powershell
python -m src.experiments.run --name forecasting_ae --dry-run
python -m src.experiments.run --tag baseline --dry-run
```

Run one enabled experiment explicitly:

```powershell
python -m src.experiments.run --name forecasting_ae
```

Force a device explicitly when needed:

```powershell
python -m src.experiments.run --name forecasting_ae --device cuda
python -m src.experiments.run --name forecasting_ae --device cpu
```

If `--device cuda` is requested but CUDA is not available, the command fails before training instead of silently falling back to CPU.

During real runs, the terminal prints progress for data preparation, training epochs, evaluation, and saved files. Shapes, device, losses, and metrics can differ by machine, dataset, and config. Example:

```text
selected experiments: 1 | planned runs: 1
=== forecasting_ae | run_001_seed_42 | seed=42 ===
preparing data...
data ready: train=(5111, 85, 128) val=(273, 85, 128) test=(273, 85, 128) slow=(324, 85, 128)
device: cuda | type: forecasting_ae
training AE (lr=0.001, epochs=60, patience=10)
  epoch 001 | train 0.176333 | val 0.121797 *
evaluating scores...
metrics: ROC=0.6707 PR=0.7912 F1@mu+2sigma=0.6150
saved checkpoint -> outputs/experiments/forecasting_ae/run_001_seed_42/model.pt
```

Use `--quiet` to suppress progress logs. The command still prints the final summary path:

```powershell
python -m src.experiments.run --name forecasting_ae --quiet
```

AAE experiments are first-class project experiments. They are disabled by default to avoid accidentally launching heavier adversarial training, but they can be inspected and run explicitly:

```powershell
python -m src.experiments.run --name reconstruction_aae --include-disabled --dry-run
python -m src.experiments.run --name reconstruction_aae --include-disabled
```

AAE sweep candidates from the notebook can also be inspected without training. They stay disabled by default because running all of them is more expensive:

```powershell
python -m src.experiments.run --tag sweep --include-disabled --dry-run
```

Repeated runs are controlled by the `repeats` field in `config/experiments.yaml`. Outputs are stored as:

```text
outputs/experiments/<experiment_name>/run_001_seed_42/
```

Each completed run writes its resolved config, metrics, history, and checkpoint. A flat summary CSV is appended at:

```text
outputs/experiments/summary.csv
```

Rerunning the same `experiment/run_id` updates that row in `summary.csv` instead of adding a duplicate, so plots do not double-count reruns. The run folder itself is overwritten for the same seed/repeat.

Plot summary metrics:

```powershell
python -m src.experiments.plot_results --summary outputs/experiments/summary.csv
```

The plot command writes PNG charts under `outputs/experiments/plots/`. The CSV can also be opened directly in Excel or LibreOffice.

## Try Suggestions Quickly

For a quick idea, clone an existing experiment and override only the values you want from the command line:

```powershell
python -m src.experiments.run --base reconstruction_aae --name quick_lam003 --set adversarial.lambda_adv=0.003 --set model.epochs=30 --device cuda --dry-run
python -m src.experiments.run --base reconstruction_aae --name quick_lam003 --set adversarial.lambda_adv=0.003 --set model.epochs=30 --device cuda
```

If the result is useful, save it into `config/experiments.yaml`:

```powershell
python -m src.experiments.create --base reconstruction_aae --name my_aae_lam003 --set adversarial.lambda_adv=0.003 --tag student
python -m src.experiments.run --name my_aae_lam003 --dry-run
```

Run a group of experiments sequentially:

```powershell
python -m src.experiments.batch --tag sweep --include-disabled --device cuda --dry-run
python -m src.experiments.batch --tag sweep --include-disabled --device cuda --continue-on-error
```

You can also create a queue file with a top-level `runs` list and run it:

```json
{
  "runs": [
    {"name": "reconstruction_aae", "include_disabled": true},
    {"tag": "sweep", "include_disabled": true}
  ]
}
```

```powershell
python -m src.experiments.batch --queue config/run_queue.yaml --device cuda --dry-run
```

For custom model ideas, scaffold the starting files:

```powershell
python -m src.experiments.scaffold_model --type my_custom_ae --class-name MyCustomAE
```

## Creating Your Own Experiments

For beginner-safe experiments, start by copying an entry in `config/experiments.yaml` and changing only config values:

```json
{
  "name": "forecasting_ae_repeat3",
  "type": "forecasting_ae",
  "enabled": true,
  "tags": ["baseline", "forecasting", "student"],
  "seed": 42,
  "repeats": 3,
  "notes": "Same forecasting AE run three times with deterministic seeds.",
  "overrides": {
    "model": {
      "epochs": 30,
      "learning_rate": 0.001
    }
  }
}
```

Use `--dry-run` before training to check the planned folders and seeds:

```powershell
python -m src.experiments.run --name forecasting_ae_repeat3 --dry-run
```

Validate the experiment file before running anything expensive:

```powershell
python -m src.config_validation
python -m src.experiments.validate
```

New experiment checklist:

- Use a unique `name`; do not reuse old names unless you want outputs mixed together.
- Use a valid `type`: `reconstruction_ae`, `forecasting_ae`, `reconstruction_aae`, or `forecasting_aae`.
- Set `enabled: true` only when the experiment is ready for tag-based runs.
- Keep `tags` as a list of strings, for example `["forecasting", "student"]`.
- Set `repeats` to an integer greater than or equal to `1`.
- Put hyperparameter changes under the right `overrides` section, usually `model`.
- Run `python -m src.experiments.validate`.
- Run `python -m src.experiments.run --name your_experiment_name --dry-run`.

To change the neural network itself, edit or add model classes under `src/models/`. For example:

- `src/models/autoencoder.py` contains `ConvAE1D`.
- `src/models/discriminator.py` contains `Discriminator1D`.
- `src/models/__init__.py` exports model classes for easier imports.

If you add a new architecture, register the new experiment `type` in `src/experiments/types.py` and add runner logic in `src/experiments/runner.py` so the CLI knows how to build and train it. Model-change checklist:

- Add the model class under `src/models/`.
- Export the class in `src/models/__init__.py`.
- Add or update a shape test in `tests/test_models.py`.
- Register the experiment `type` in `src/experiments/types.py`.
- Add the build/train dispatch in `src/experiments/runner.py`.
- Add or update an experiment runner test in `tests/test_experiments.py`.

Common symptoms:

- `Unknown experiment type`: the config `type` has a typo or validation does not know the new type.
- `generator_loss must be one of ...`: AAE currently accepts `linear` or `hinge`.
- `ImportError`: the new model class may not be exported from `src/models/__init__.py`.
- Shape mismatch in tests: the model output shape no longer matches the training target.

After model changes, run:

```powershell
python -m pytest tests/test_models.py tests/test_experiments.py -q
python -m src.experiments.validate
python -m src.experiments.run --list
python -m src.experiments.run --name your_experiment_name --dry-run
```

## Training

For reproducible comparisons, prefer the experiment runner above because it saves per-run config, metrics, history, checkpoints, and summary rows under `outputs/experiments/`.

The older training entry point is still available for the simple reconstruction/forecasting AE workflow only:

```powershell
python -m src.training.train --config config/config.yaml
```

Outputs are written under the configured `outputs/ae_compare/` directory.
